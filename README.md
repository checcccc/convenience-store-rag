# 便利店 AI 助手 🏪

> 站在货架前，面对几百种商品，你只想找到"对的那一个"——**说人话就行**。

## 这是什么

一个用 Python 写的便利店商品助手。你只要用大白话描述需求，它就能从一堆商品里帮你捞出最合适的几款，再用一句话告诉你"为什么是这几款"。

比如你说 **"5元以下的无糖饮料"**，它会回你：

> 「5元以下的无糖饮料有零度可乐 330ml 罐装（3.5元）和东方树叶茉莉花茶 500ml（4.5元）。」

同时把商品列表也给你：名称、分类、品牌、价格，一目了然。

## 核心思路：不让 AI 瞎编

很多 AI 助手的毛病是"一本正经地胡说八道"——你没问的商品它也能给你编出来。这个项目的解法叫 **RAG（检索增强生成）**，一句话就是：

1. **先检索**：像店员一样，先从货架上把"可能相关"的商品挑出来——**这一步靠真实数据，不靠 AI 想象**。
2. **再生成**：让 AI 只基于挑出来的这几款商品，把话说清楚。**AI 被"钉死"在检索结果上，编不出花来。**

所以哪怕 AI 想吹牛，它手里也只有检索给它的那几张"牌"。

## 框架拆解：它到底怎么工作

把整个系统想象成一条**"找货流水线"**，你的话从这头进去，答案从那头出来：

```
你说一句话
   │
   ▼
① 听懂你在说啥 —— 让 AI 把话拆成两部分：
   · 硬条件（"5元以下""饮料"这类能精确筛的）
   · 软意图（"无糖""不含咖啡因"这类要靠"感觉"的）
   │
   ▼
② 三个"店员"分头去找 —— 最关键的一步，三种找法互补：
   · 店员A（关键词检索 BM25）：只认字面，"可口可乐"四个字一打一个准。
   · 店员B（语义检索 向量）：认意思，"提神醒脑"能找到咖啡，哪怕没有"咖啡"俩字。
   · 店员C（结构化过滤）：按分类 / 品牌 / 价格硬筛。
   │
   ▼
③ 把三个店员的推荐合起来排序 —— 用 RRF（倒数排名融合）：
   三个店员打分标准不一样，没法直接比大小，那就只看"排名"，
   谁在多个店员那里都靠前，谁就排前面。
   │
   ▼
④ 让 AI 把结果"说成人话" —— 基于最终挑出的商品，生成一句小结。
   （AI 只能引用给它的商品，不能自由发挥）
   │
   ▼
输出：一句话小结 + 商品列表
```

**一句话总结这套框架**：检索（找得准）+ 生成（说得清），中间用 RRF 把"字面"和"语义"两条路子拧成一股。

## 我是怎么做出来的（制作流程）

> 这是这个项目最有意思的部分——它不只是一堆能跑的代码，更是一套"从想法到上线"的完整流程。

1. **先立框架，不急着写代码**。先想清楚"要解决什么问题、数据长什么样、检索怎么搭"，画出一张 5 层架构图，把每个模块的边界和接口都定下来。这一步省下的返工，比后面写代码省的时间多得多。

2. **写设计文档（spec）**。把需求、技术选型、数据模型、检索策略、生成策略白纸黑字写下来，当作后面所有工作的"宪法"。以后遇到分歧，翻文档，不靠拍脑袋。

3. **写实现计划（plan）**。把大目标拆成 8 个小任务，每个任务都规定好"要建哪些文件、函数叫什么、用什么测试证明它对了"。这样每做一步都有明确的"完成标准"。

4. **TDD 一路绿灯**。每个功能都是"先写一个会失败的测试 → 看它红 → 写代码让它绿 → 提交"。最后 **35 个测试全绿**，每个模块都能单独讲清楚、单独测。

5. **真实联调，揪出真 bug**。接入真实的 DeepSeek 和 BGE 模型后，才发现两个只有真跑才会暴露的问题：
   - LLM 会把"无糖饮料"错当成商品小类，导致把商品全筛没了 → 加了"分类校验"兜底；
   - LLM 不按格式输出 `summary` 字段 → 修了提示词。

6. **上传 GitHub**，让这套东西留个档、也能给人看。

**心得**：RAG 的难点从来不是"调用一下大模型"，而是**怎么把检索做准**。三种召回互补、RRF 融合、约束校验兜底——这些"脏活累活"，才是让 AI 助手真正可用的关键。

## 怎么跑起来

```bash
git clone https://github.com/checcccc/convenience-store-rag.git
cd convenience-store-rag
pip install -r requirements.txt

# 首次运行会下载 BGE 模型（国内建议用镜像加速，Windows PowerShell）：
$env:HF_ENDPOINT = "https://hf-mirror.com"
```

### 方式一：离线跑（无需任何 key，开箱即用）

```bash
python -m src.app "无糖、不含咖啡因的饮料"
```

### 方式二：接入国内 LLM（完整效果）

```bash
$env:LLM_BASE_URL = "https://api.deepseek.com"
$env:LLM_API_KEY  = "你的 key"
python -m src.app "5元以下的无糖饮料"
```

> 配了 key，检索会加入 AI 抽取的"分类/品牌/价格"硬过滤，小结也由 AI 生成；不配 key 也能跑通语义+关键词检索，只是小结是确定性文案。

## 技术栈

| 部分 | 用什么 | 为什么 |
|------|--------|--------|
| 语义检索 | BGE 中文向量模型 | 中文语义准、本地免费跑 |
| 关键词检索 | BM25 + jieba 分词 | 字面精确匹配 |
| 融合排序 | RRF（倒数排名融合） | 把多路召回公平合成 |
| 向量库 | Chroma | 本地零配置 |
| 生成 | DeepSeek 等国内 LLM | 便宜、中文好、国内直连 |
| 语言 | Python | RAG 生态最成熟 |
